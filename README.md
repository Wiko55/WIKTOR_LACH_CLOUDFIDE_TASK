# Data Engineering Assignment

## Project Overview & Structure

This project provides a safe pandas expression engine and a sales pipeline for
cleaning order records and aggregating revenue by region.

- `solution.py` implements `add_virtual_column`.
- `pipeline.py` provides `clean_sales_data` and `run_pipeline`.
- `analysis_notebook.ipynb` contains the analysis of the sales data.
- `sales.csv` is the input dataset.
- `revenue_by_region.csv` is generated by the pipeline.
- `test_solution.py`, `test_virtual_column.py`, and `test_pipeline.py` cover
  expression evaluation and pipeline behavior.
- `pyproject.toml` and `uv.lock` define the `uv` environment; `requirements.txt`
  supports pip installation.

## Setup & Usage

Python 3.12 or newer is required. Install with `uv`:

```bash
uv sync
uv run python pipeline.py
uv run pytest
```

Or create a virtual environment and install with pip:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python pipeline.py
pytest
```

By default, the pipeline reads and writes CSVs beside `pipeline.py`.
`run_pipeline` accepts custom paths for temporary or alternate files.

## Assumptions & Design Decisions

**Part 1 — `add_virtual_column`**

- **Safe Expression Evaluation via Reverse Polish Notation (RPN):** Seeing
  multi-operator expressions like `quantity * unit_price - discount` immediately
  reminded me of studying Reverse Polish Notation (Łukasiewicz notation) during
  my mathematics degree. Implementing Dijkstra's Shunting-yard algorithm to
  convert infix expressions into RPN was a deliberate engineering choice—it
  guarantees proper operator precedence (`*` before `+` and `-`) and
  left-associativity without relying on unsafe `eval()` or overly permissive
  parsers, while preserving full control over strict syntax validation.
- Labels must match `^[a-zA-Z_]+$`; referenced columns must exist and contain
  numeric, non-boolean values.
- Supports binary `+`, `-`, and `*` on existing columns only; no parentheses,
  unary operators, or numeric literals.

**Part 2 — sales pipeline**

- Headers are normalized; repeated headers, `TOTAL`, and exact duplicate rows
  (keeping the first) are removed.
- Trim and capitalize categories, strip quantity whitespace, and normalize
  decimal commas. Invalid non-empty values, missing quantities/categories, or
  invalid dates raise errors instead of being silently dropped.
- Blank discounts become `0.0`. Missing prices use the product median only if
  observed prices are consistent; all eight products pass this check.
- Retain negative and very large quantities: they may represent returns or bulk
  orders. Confirm with sales stakeholders before production decisions.

## Data Quality Issues in `sales.csv`

Counts use 1,500 de-duplicated detail rows except where raw rows are specified;
categories can overlap.

| Issue | Affected Rows | Handling Strategy |
|---|---:|---|
| Trailing whitespace in `Quantity ` header | 1 label | Normalize header |
| Repeated embedded header row | 1 raw row | Remove before processing |
| `TOTAL` summary row | 1 raw row | Remove before processing |
| Exact duplicate records | 5 duplicate copies (10 rows in groups) | Keep one copy |
| Region casing or surrounding whitespace | 15 rows (8 whitespace) | Trim and capitalize |
| Missing unit prices | 4 rows (2 Keyboard, 2 Printer paper) | Impute product median |
| Blank discounts | 959 rows (3 also missing price) | Set to `0.0` |
| Decimal-comma unit prices | 7 rows | Normalize and parse |
| Negative quantities | 6 rows (`-2` to `-5`) | Retain; may be returns; confirm with sales |
